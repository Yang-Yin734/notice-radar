# 把抓取放到国内云函数（免费、不用一直开电脑）

**为什么需要它**：GitHub 的 runner 在**境外**，抓国内教育网站点实测单轮成功率只有四成左右
（我用两个互不相关的境外中转实测：四个页面**全部**在 ~20 秒后超时，HTTP 522）。
放在国内云函数上跑，成功率接近 100% —— 而阿里云函数计算（FC）和腾讯云云函数（SCF）
都有**长期免费额度**，个人这点调用量远远用不完。

> 顺带说明：这条路径**不替代** GitHub Actions。最省心的组合是
> 「GitHub 继续抓（能抓多少算多少，网页/应用的归档也靠它）+ 国内云函数兜底补齐」。
> 云函数这边**完全无状态**（不需要数据库、不需要对象存储），所以部署很轻。

---

## 一、打包（在你电脑上执行一次）

```bash
npm run build:serverless
```

产物：

| 路径 | 用途 |
|---|---|
| `deploy/serverless/build/` | 上传目录（handler + 编译好的 JS + 配置 + 生产依赖） |
| `deploy/serverless/notice-radar-serverless.zip` | **直接上传这个压缩包** |

打包前建议先本地自检一次（`DRY_RUN`，只预览不真推送）：

```bash
node tools/verify-serverless.mjs
```

它会用打包产物真抓一遍、跑一次摘要，但不发送。看到「✓ 自检通过」再去云端部署。

## 二、部署（二选一）

### 方案甲：阿里云函数计算 FC

1. 控制台 → **函数计算 FC** → 创建函数 → **Web 函数/事件函数**都行，选**事件函数**
2. 运行环境：**Node.js 20**（18 也行）
3. 代码：选**上传 ZIP 包**，上传 `notice-radar-serverless.zip`
4. 请求处理程序（Handler）：`handler.fcHandler`
5. **环境变量**（配置 → 环境变量）：
   | 名称 | 值 | 说明 |
   |---|---|---|
   | `SERVERCHAN_KEY` | `SCT...` | 必填。sct.ftqq.com 扫码登录后拿，**并关注它的服务号** |
   | `MODE` | `window` 或 `digest` | 见下面「两种模式」 |
   | `WINDOW_HOURS` | `0.25` | `window` 模式的窗口（小时） |
   | `DRY_RUN` | `1` | **首次务必先填 1**，验证通了再删掉 |
6. **触发器** → 创建**定时触发器**：
   - 模式 A（近实时）：`MODE=window`，Cron 表达式 `0 */10 * * * * *`（每 10 分钟）
   - 模式 B（每天一次完整日报）：`MODE=digest`，Cron 表达式 `0 10 8 * * *`（每天 08:10）
7. 测试：配置里点**测试函数** → 看返回的 `log` 里有没有 `serverchan：HTTP 200 已投递`

### 方案乙：腾讯云云函数 SCF

1. 控制台 → **云函数 SCF** → 新建 → **从头开始**
2. 运行环境：**Node.js 18** 或 20；提交方法选**上传 zip 包**，上传同一个 zip
3. **执行方法**：`handler.main_handler`（如果提示找不到，改成 `handler.cjs` 里的 `main_handler`，
   或在函数配置里把入口写成 `handler.cjs` 的 `main_handler` —— CJS 包装已经一并打进去了）
4. 环境变量、定时触发器与上面方案甲相同（SCF 的 Cron 表达式是 **7 段**，形如 `0 */10 * * * * *`）
5. 测试：函数 → 测试 → 看返回 JSON 里的 `pushedToWechat`

## 三、两种模式怎么选

| 模式 | 窗口 | 建议频率 | 特点 |
|---|---|---|---|
| `window` | `WINDOW_HOURS`（默认 15 分钟） | 每 10 分钟 | **近实时**：新通知十几分钟内到微信；窗口小于间隔，同一条不会重复推。缺点：某次调用失败时那条会漏（由下面的 digest 兜底） |
| `digest` | `HOURS`（默认 24 小时） | 每天 1 次 | **完整兜底**：一天里所有新通知合成一条；窗口内没新通知就**什么都不发**（不会打扰） |

> 推荐：**两个函数都建**（同一个 zip 上传两次，环境变量不同）——
> `window` 负责快，`digest` 负责不漏。两个加起来仍在免费额度内。

## 四、费用（为什么说是零成本）

| 项目 | 免费额度 | 你的用量 |
|---|---|---|
| 阿里云 FC / 腾讯云 SCF 调用次数 | 每月约 100 万次 | 每 10 分钟一次 ≈ **4,300 次/月** |
| 计算资源 | 每月 40 万 GB·s 量级 | 每次约 3~8 秒 × 128MB ≈ **1,800 GB·s/月** |
| 存储 | 无（**本方案完全无状态**） | 0 |

所以个人使用**不会产生费用**。唯一门槛是云账号需要**实名认证**。

## 五、排查

| 现象 | 原因 |
|---|---|
| 返回 `找不到 .../dist-serverless/cli.js` | zip 传错了（要传整个包，不是只传 handler） |
| 返回 `没有配置 SERVERCHAN_KEY` | 环境变量没配，或名字拼错 |
| `log` 里 `[抓取]` 全是失败 | 云函数地域选到了海外（选**国内地域**，如北京/上海/广州） |
| 微信没收到，但 `pushedToWechat= true` | Server酱 侧没关注服务号，或额度用尽（Server酱 免费版每天有条数上限） |
| 想临时停掉 | 删掉定时触发器，或把 `DRY_RUN` 设为 `1` |

## 六、注意事项

- 本方案只做**抓取 + 推送**；它不会更新仓库里的网页/应用归档（那部分仍由 GitHub Actions 负责）。
  想让网页/应用也吃到这份数据，需要它把状态提交回仓库 —— 不推荐（国内到 GitHub 的连接本身就不稳）。
- 学院那两个**需要真浏览器**的 WAF 源在云函数上跑不了（除非自己塞一个无头浏览器，体积会很大）。
  它们仍由 GitHub 的 `poll-math` 每天跑一次；或按 README 的「完全不用 GitHub」在本机跑。
- 请遵守学校站点的访问规则：默认已经是串行 + 间隔抓取（`--delay`），不要为了"更快"改成并发猛打。
