# 把通知推到微信（推送通道配置）

> 这一页回答一个问题：**怎么让通知真正落到我的微信里？**
> 每条通道都是 1 分钟配置，配好跑一条命令就能验证。

---

## 先说清现实：为什么不能做"微信官方授权"

很多人第一反应是"用微信公众号授权登录，然后发模板消息"。这条路对个人项目**走不通**，原因是微信官方的限制，不是本项目偷懒：

| 官方能力 | 门槛 | 个人开发者 |
|---|---|---|
| 服务号**模板消息** / **订阅通知** | 需要**已认证的服务号**（企业主体，300 元/年）+ 自建服务器做 OAuth 拿用户 openid | ❌ 个人主体申请不到模板消息 |
| 小程序订阅消息 | 需要小程序（个人可注册）+ 用户每次授权、模板受限 | ⚠️ 能做但要求用户装小程序，且每次推送都要用户点授权 |
| 企业微信应用消息 | 注册企业微信（免费，个人也能注册）+ 建应用 | ✅ 可行，且**能落到微信**（见下） |

所以"推到微信"实际是三条个人可行的路 —— 本项目**全部都支持**：

| 通道 | 落地到哪 | 费用/配额 | 配置难度 | 真·微信授权？ |
|---|---|---|---|---|
| **WxPusher**（推荐） | **微信**（公众号会话） | 免费，额度宽松 | ★ 扫码关注公众号 | ✅ 微信扫码登录 + 关注公众号授权 |
| **企业微信群机器人** | 企业微信；开"微信插件"后**微信也能收到** | 免费，无月配额 | ★ 建群加机器人 | ⚠️ 授权在企业微信侧 |
| **企业微信自建应用** | 企业微信（可发给指定人）；同样可经微信插件进微信 | 免费 | ★★ 建应用 + 拿 Secret | ⚠️ 同上 |
| Server酱（原有） | 微信（第三方中转） | 免费版每天有条数上限 | ★ 扫码拿 SendKey | ❌ 第三方中转 |

> **建议**：`wxpusher` + `wecom-bot` 两个都配。前者是"扫码授权直达微信"，后者是"免费无配额兜底"；
> 任一通道成功就算推送成功，多配几个不会重复打扰（同一轮只推一次）。

## 1. WxPusher（最接近"微信授权"，推荐）

**它是怎么授权的**：你用**微信扫码**登录 WxPusher 后台 → 创建一个应用 → 再关注它的公众号
→ 你的微信就"授权"了这个应用给你发消息，之后通知由公众号直接推送到你的微信会话里。

**步骤**

1. 打开 <https://wxpusher.zjiecode.com/> → 右上角**微信扫码登录**
2. 「应用管理」→ 新建应用（名字随便，比如 `通知雷达`）→ 复制 **appToken**（形如 `AT_xxxxx`）
3. 「用户管理」/ 应用详情页 → 用微信**关注二维码里的公众号** → 关注后回到后台，能看到你的 **UID**（形如 `UID_xxxxx`）
4. 把这两个值配到运行环境：

   | 变量 | 值 |
   |---|---|
   | `WXPUSHER_APP_TOKEN` | 刚才复制的 `AT_…` |
   | `WXPUSHER_UIDS` | 你的 `UID_…`（多个用英文逗号分隔） |

5. 打开配置里的通道开关（`config/schools/uestc.yaml`）：

   ```yaml
   notify:
     - type: wxpusher          # ← 把 enabled 改成 true
       enabled: true
   ```

6. **验证**：

   ```bash
   radr test-notify --channel=wxpusher
   ```

   手机上收到"推送通道测试"就成功了。失败时输出会直接告诉你缺哪个变量或接口返回了什么。

**GitHub Actions 上**：仓库 → Settings → Secrets and variables → Actions → New repository secret，
添加 `WXPUSHER_APP_TOKEN` 与 `WXPUSHER_UIDS`（工作流已经会把它们传给命令，不用改 YAML）。

## 2. 企业微信群机器人（免费、最稳、可进微信）

1. 手机或电脑装**企业微信**（个人也能免费注册一个企业，不需要营业执照审核）
2. 建一个群（可以只有你自己）→ 群设置 → **群机器人** → 添加 → 复制 **Webhook 地址**
   （形如 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxxx`）
3. **想让它出现在微信里**：企业微信 → 我 → 设置 → **微信插件**（或管理后台 → 微信插件）→ 用微信扫码开启。
   开启后，企业微信的消息会同步到微信里的"企业微信"会话 ✅
4. 配置：

   | 变量 | 值 |
   |---|---|
   | `WECOM_BOT_WEBHOOK` | 刚才复制的完整 webhook |

   ```yaml
   notify:
     - type: wecom-bot
       enabled: true
   ```

5. **验证**：`radr test-notify --channel=wecom-bot`

> 群机器人没有独立标题字段，所以推送会把标题并进正文首行；正文用 Markdown（链接可点）。

---

## 3. 企业微信自建应用（能发给指定人）

适合"想只推给自己、又不想建群"的情况。

1. 企业微信管理后台 → **应用管理** → 自建 → 创建应用 → 记下 **AgentId** 与 **Secret**
2. 管理后台 → 我的企业 → 复制 **企业 ID**（CorpID）
3. 在应用里把可见范围设成包含你自己；你的 **UserID** 在「通讯录」里能看到（或直接填 `@all`）
4. 配置：

   | 变量 | 值 |
   |---|---|
   | `WECOM_CORP_ID` | 企业 ID |
   | `WECOM_SECRET` | 应用 Secret |
   | `WECOM_AGENT_ID` | 应用 AgentId（数字） |
   | `WECOM_TOUSER` | 你的 UserID，或 `@all` |

   ```yaml
   notify:
     - type: wecom-app
       enabled: true
   ```

5. **验证**：`radr test-notify --channel=wecom-app`

> 同样建议开启**微信插件**，这样消息在微信里也能看到。

## 4. Server酱（原有通道）

`SERVERCHAN_KEY`（形如 `SCT…`），扫码绑定即可。免费版每天有条数上限；
**配额用尽时本项目会明确提示**（不会让你以为是代码坏了），这也是建议再加一条企业微信/WxPusher 的原因。

## 常见问题

**Q：配了多个通道，会收到好几条重复消息吗？**
同一条通知只发一次，所有启用通道各发一份（这是"多通道"的本意：一份微信、一份邮件备份）。
不想收某一路就把它的 `enabled` 改成 `false`。

**Q：怎么只测某一个通道？**
`radr test-notify --channel=wxpusher`（可选 `serverchan` / `wecom-bot` / `wecom-app` / `email` / `webhook` / `stdout`）。

**Q：推送失败时怎么排查？**
每一次推送的结果都会写进 `data/last-notify.json`（提交进仓库，可直接查证），
里面含通道名、成功与否、以及接口返回的原因（密钥已脱敏）。
失败原因也尽量翻译成人话：缺哪个环境变量、配额用尽、webhook 格式不对等。

**Q：能推到 Telegram / 钉钉 / 飞书吗？**
能。用通用 `webhook` 通道（`type: webhook`）把 JSON `{title, markdown}` POST 到你的地址即可。

**Q：邮件通道怎么配？**
`SMTP_URL`（`smtps://user:pass@smtp.example.com:465`）或 `SMTP_HOST` + `SMTP_USER` + `SMTP_PASS`，
再加 `MAIL_TO` / `MAIL_FROM`；需要可选依赖：`npm i nodemailer`。邮件会同时发纯文本与 HTML（链接可点）。
