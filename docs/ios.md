# iOS（iPhone / iPad）怎么用这个应用

先说结论：**iOS 上"下载一个安装包直接装"这件事不存在**。这不是本项目没做，是 Apple 的规则——
任何要在 iPhone 上运行的原生应用，都必须用 Apple 签发的证书签名，否则系统拒绝安装。
下面三条路，按推荐程度排序。

---

## 路线一：Safari「添加到主屏幕」（推荐，现在就能用，零成本）

这是 Apple 官方给**网页应用**的安装方式，体验和原生应用基本一致：

1. 用 **Safari** 打开 <https://yang-yin734.github.io/notice-radar/>
   （必须是 Safari，Chrome/微信内置浏览器都不行——iOS 上它们调不出这个入口）
2. 点底部中间的 **分享** 按钮
3. 选 **添加到主屏幕** → 右上角 **添加**

装好之后：

- 桌面上出现独立图标，名字是「通知雷达」
- 点开是**全屏应用**（没有浏览器地址栏），有启动图
- **可离线**翻已缓存的通知（Service Worker 缓存）
- 支持**应用内更新**：新版本外壳就绪时会提示"点右侧立即生效"
- **永不过期**，不需要 Apple 账号，不需要电脑

> 顺带一提：iOS 16.4 起，添加到主屏幕的网页应用还能收**系统级 Web 推送**。
> 本项目目前**没有做 Web Push**：通知走你在配置里启用的通用通道（webhook / 邮件，见 README「推送通道」）；
> 如果你更想要 iOS 原生通知，这是一个可以加的功能（需要一对 VAPID 密钥 + 一个发送端）。

---

## 路线二：App Store / TestFlight（要花钱+要 Mac）

如果你确实想要一个上架的原生包，需要：

| 需要的 | 说明 |
|---|---|
| Apple Developer Program | **$99/年**，个人或公司账号 |
| 一台 Mac | 必须用 Xcode 构建（GitHub 的 macOS runner 也能跑，但要先有账号与证书） |
| 签名证书 + Provisioning Profile | 在 Apple 开发者后台生成，导入 Xcode 或 CI |
| App Store Connect 记录 | 建 App、填隐私说明、截图、审核（通常几天） |

技术上，这个项目做成 iOS 应用的路径是：用 WKWebView 包一层打开同一个网址（等价于 Android 侧的 TWA），
再用 Xcode 归档、签名、上传 TestFlight。**本项目没有 Apple 账号，所以这一步无法代做**；
代码结构（`config/` + `src/`）与 `android/` 的 TWA 工程是分离的，加一个 `ios/` 工程不会影响现有功能。

---

## 路线三：侧载未签名 IPA（能装，但很折腾）

如果你只想自己装上用，且不介意折腾：

1. 需要一个能在本地签名的工具：**Sideloadly**（Windows/macOS）或 **AltStore**
2. 用你自己的 Apple ID 免费签名——**免费账号签出来的应用 7 天后失效**，需要重新连电脑签一次
3. 同一个免费账号最多同时装 3 个自签应用

本项目目前**没有提供 IPA 文件**（因为没签名，装不了；而签名必须有 Apple 证书）。
如果你要走这条路，我可以补一个 macOS runner 上的构建流程，产出**未签名 IPA** 供 Sideloadly 签名安装——
需要你说一声。

## 和 Android 的对比（为什么体验差这么多）

| | Android | iOS |
|---|---|---|
| 直接下载安装包 | ✅ APK，随时装 | ❌ 系统不允许 |
| 网页应用装到桌面 | ✅ Chrome「安装应用」 | ✅ Safari「添加到主屏幕」 |
| 免开发者账号 | ✅ | ✅（仅网页应用这条路） |
| 全屏无地址栏 | ✅（TWA + assetlinks） | ✅（添加到主屏幕后自动全屏） |
| 系统级推送 | ✅（走你配的 webhook/邮件通道） | 需要 Web Push（16.4+）或上架原生应用 |

所以在这个项目里：**Android 给 APK，iOS 给"添加到主屏幕"**——两者都是各自平台上最省事、最可靠的安装方式。
